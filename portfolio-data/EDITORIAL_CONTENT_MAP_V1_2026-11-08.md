# SHOWTIME — Evidence-backed Content Map v1
**Date:** 08 Nov 2026  
**Purpose:** editorial product of the *discovery / verification / curation* stage. This is NOT a UI design, code brief, public website launch or a freeze of user submissions.

## Editorial decision
SHOWTIME is a coherent creative exhibition of actual work across event production, music/live performance, game design, AI-assisted tools and content, plus research/learning. A project is not promoted because it has an impressive logo or many metrics. It is promoted when a visitor can see a distinctive output and a defensible owner contribution.

A single project may support multiple hiring narratives but it is **counted once**. Supporting pages/visuals may cross-link instead of duplicating it.

### Source/claim classes
- **P — independently/publicly source-backed:** verified public product page, organizer source, or authentic published media link (does not automatically certify personal contribution).
- **O — owner directly reported:** role/outcome/identity supplied by the user; usable as self-reported portfolio claim, no external certification implied.
- **A — actual artifact examined:** authenticated user Drive/GitHub file, source or pixels inspected. Document existence is not proof of public publication or all claimed results.
- **H — historical/build-specific:** accepted source for a prior version, not current rebuild or release.
- **U — unknown/blocked:** information unavailable. Never fill with guesses.

## Publication and integrity gates
1. User does **not** need impressive revenue/views/play counts, nor a complete career timeline, nor a job title for every photograph.
2. Never claim AI-vibecoded output was written manually line-by-line. Accurately portray creative direction, product choices, collaboration and quality review.
3. Third-party event photo/video/audio links are not rehosting licenses.
4. Be precise about creator credits, photographer rights and team roles.
5. For an externally playable game, verify actual link access and the gameplay/mode features before advertising them.
6. Current project source has to beat historical README/test evidence for live product claims.
7. A document with an internal role table demonstrates planned responsibilities, not proof that all planned media were shipped.
8. Raw transcripts, thesis participant data, confidential business information and private project Drive links stay out of the portfolio repo.
9. No user-facing UI, HTML, website build, prototype or deployment is authorized by this content map.
