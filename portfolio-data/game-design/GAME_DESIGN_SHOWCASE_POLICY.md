## No player/revenue metrics is a design choice, not a blocker
**Do not make number cards like "0 players", "0 revenue", misleading badges such as "successful launch" or unsupported adoption claims.** Exclude an entire traction section until there is actual evidence. Prefer:
1. Playable public build and stable external link.
2. What is distinctive about gameplay: characters, abilities, combat decisions, world rules.
3. Selected authentic in-game screenshot/video captures (no mock shots pretending to be production).
4. The owner's product/design direction and AI-assisted iteration process.
5. Verifiable development milestones and regressions—label test results with tested version/SHA if used.
6. Genuine feedback or reach metrics only if later collected with source and time window.

## Release acceptance / source policy
Before shipping portfolio pages, record:
- game URL and platform, access from anonymous browser, correct game title, up-to-date visuals
- whether UI game launch works and can be played, or merely displays a launcher
- actual currently delivered modes vs planned modes, native vs web/desktop export
- rights to rehost game screenshots/character art, attribution of external assets
- credit specificity: user's direction, design and QA vs AI-generated/agent-implemented code
- dates and named source versions if claims include technical validation
- accessibility/performance quality of portfolio embeds; fallback links
